# APP／IM 对接问题单

起草：2026-09-23　｜　发给：APP 技术负责人（人员待确认）　｜　答复期限：待确认

## 背景

我们在准备保险经纪智能体上线：经纪在 APP 内通过会话和 H5 页面完成参数确认、计划书任务查询、讲解包复核和客户跟进。目标范围见[分阶段交付计划](../../delivery-plan-v1.md) §1、§5.6；通道与架构边界见[工程评审 v2](../../insurance-agent-v2.md) §3–§4。

如实说明当前状态：我方只有本地原型，使用演示会话登录，**尚未接入 APP 登录、IM 或推送**，接口状态返回 `im: prototype-only`。本问题单用于确定对接方式，不代表任何方案或供应商已选定。

## 填写说明

- 每题请写：答复、依据（文档或接口说明链接）、答复人、日期。不清楚请写“未知”，不要估计。
- **不要在本文或聊天中填写**密钥、令牌、测试账号密码或真实客户资料。需要测试账号时，只写负责人和申请方式。
- 对接方案需满足我方后端的固定约束：
  1. 身份只取自我方后端校验过的会话，不信任请求正文或 URL 中自报的经纪、机构、客户 ID。
  2. 访问客户、任务、文件时逐条按机构＋经纪鉴权；知道 ID 不等于有权访问。
  3. 模型回复在发送前完成合规审查，不能由模型直接流式发到 IM。
  4. 推送只带最少信息（如“任务已完成，请登录查看”），不带客户健康信息、保单详情或长期有效的下载链接。

## 8. 联调验收口径（供知悉）

- 完整历史、多轮上下文、离线通知、多端一致性分别验收；“消息能发出”不等于 IM 完成（[交付计划](../../delivery-plan-v1.md) §5.6）。
- 重复回调不重复创建任务；IM 断线不丢任务；通知失败时经纪仍能在 APP 内查到任务（交付计划 §3 第 5 步，[工程评审 v2](../../insurance-agent-v2.md) §4）。
- 修改客户 ID 或任务 ID 访问他人数据必须被拒绝。
