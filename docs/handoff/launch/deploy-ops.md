# 生产部署与运维需求

起草：2026-09-23　｜　发给：运维负责人、技术负责人、隐私／法务负责人（人员均待确认）　｜　答复期限：待确认

## 现状

- 当前只有本地原型：服务只监听本机，**拒绝以 production 模式启动**；任务数据存本机 SQLite，文件存本地目录；登录为演示会话；未部署到任何服务器。
- 香港 Python（M1b）、Dify（M2b）、APP IM 均未接入，见[项目接续记录](../../progress-2026-09-22.md)和 [AGENTS.md](../../../AGENTS.md) §1。
- 香港现有电脑可用于初步验证；能否长期运行需检查供电、网络、系统维护、账户隔离和运维安排（[交付计划](../../delivery-plan-v1.md) §5.2）。
- 下文所有取值、人员、时限在确认前均为“待确认”。

### 1.2 需确认的问题

1. 云服务还是自有机房？供应商与地域？
2. 开发、测试、预发布、生产是否完全独立（数据库、密钥、门户账号不共用）？
3. 业务后端与香港 Python 之间走什么网络（专线／VPN／公网＋TLS）？双方如何互相鉴权？
4. Worker 访问保司门户的出口 IP 是否需要固定或向保司报备？
5. 单实例还是多实例？**当前防重复执行只在共用同一 SQLite 的进程间验证过**；多实例或分布式部署需另行设计和验证（[Python 对接契约](../../python-integration-contract.md) §4）。
6. 服务器时间同步：工具请求签名要求与后端时间相差不超过一分钟（[M2a-2 契约](../../m2a2-offline-tools.md)）。
7. 域名与 TLS 证书由谁申请和续期？
8. 谁有权登录生产服务器和数据库？是否需要审批和操作审计？
9. 谁有权发布？是否需要变更审批？
10. 数据流清单（数据类别、处理方、地域、保留期、删除方式、备份位置、运维访问、合同依据）须在使用真实客户资料前完成（[工程评审 v2](../../insurance-agent-v2.md) §5.1）。由谁负责？

### 1.3 上线前必须补齐（原型尚未具备）

- 企业登录替换演示会话；生产环境禁止 mock 执行器，误配置时启动失败或阻止正式任务（[AGENTS.md](../../../AGENTS.md) §2 第 2 条）。
- 密钥只放受控密钥存储；日志、审计正文、聊天中不出现密钥、Cookie、令牌或完整客户敏感信息。
- TLS、限流、审计保留期及运维验收（[M2a-2 契约](../../m2a2-offline-tools.md)“待输入／待环境”）。

## 2. 数据库备份与恢复演练

### 2.1 备份范围

- 数据库：草稿与确认快照、任务及状态、任务租约、执行账号占用、幂等记录、讲解包版本、跟进卡、产品暂停状态、Dify 运行与回调记录、审计事件。
- 文件存储：官方 PDF、讲解包导出件。数据库记录文件 hash，下载时会复核。
- 配置：产品目录、schema 版本、运营参数（[运营参数确认表](ops-params.md)）。
- 备份中不含明文凭据；密钥由密钥存储自身的备份机制负责。

### 2.2 待确认项

| 项目 | 说明 | 取值 | 由谁确认 |
| --- | --- | --- | --- |
| 备份频率 | 数据库、文件存储分别多久备份一次 | 待确认 | 运维＋业务负责人 |
| 可接受数据丢失（RPO） | 故障时最多丢失多长时间的数据 | 待确认 | 业务负责人 |
| 恢复时间上限（RTO） | 故障到恢复服务的最长时间 | 待确认 | 业务负责人 |
| 备份保留期限与份数 | 与文件存储期限、删除要求联动 | 待确认 | 业务负责人＋隐私／法务 |
| 备份存放位置与地域 | 须与数据流清单一致 | 待确认 | 运维＋隐私／法务 |
| 备份加密与恢复权限 | 谁能读取备份、谁能执行恢复 | 待确认 | 运维 |
| 恢复演练频率 | 上线前须有演练记录（[交付计划](../../delivery-plan-v1.md) §7），之后的频率 | 待确认 | 运维＋测试 |

### 2.3 恢复演练通过标准

在隔离环境从备份恢复后逐项核对：

1. 任务数量和状态与备份时点一致，没有丢失或重复。
2. 文件 hash 与记录一致。数据库与文件备份时点不一致造成的缺失或不符，下载被拒绝，而不是交付错误文件。
3. 恢复前处于 `running`／`validating` 的**真实**任务不自动重做，进入人工核实（[AGENTS.md](../../../AGENTS.md) §2 第 4 条）。
4. 执行账号占用记录保留，未经人工核实不释放。
5. 用相同幂等键再次提交，返回原任务，不重复创建。
6. 经纪／机构隔离仍有效；审计记录连续可查。
7. 实际恢复耗时与 RTO 对比。

演练记录：日期、执行人、备份时点、恢复耗时、以上 7 项结果、发现的问题及处理。

## 3. 监控告警项

阈值统一待确认；接收人见第 5 节。

| 类别 | 告警项 | 原因 |
| --- | --- | --- |
| 服务 | 业务后端、Worker、Python 服务不可用或健康检查失败 | 经纪无法提交，或任务停滞 |
| 任务 | Worker 心跳／租约续租失败、任务租约过期 | 执行可能中断，需判断是否转人工 |
| 任务 | 排队任务数、最长排队时长超过“最大排队时长” | 交付变慢（见[运营参数](ops-params.md)） |
| 任务 | 新增人工任务；人工任务超时未处理 | 经纪等待，执行账号被占用 |
| 任务 | 执行账号长时间占用 | 占用不会自动释放，会阻塞同账号所有后续任务 |
| 门户 | `AUTH_REQUIRED`、`MFA_REQUIRED`、`PORTAL_CHANGED`、`RESULT_UNKNOWN`、`TRANSIENT_NETWORK_ERROR` 次数 | 门户登录或页面变化；`PORTAL_CHANGED` 会自动暂停产品 |
| 门户 | 产品被暂停或恢复 | 影响经纪提交 |
| 文件 | `PDF_MISMATCH`；下载时 hash 不符（`FILE_INTEGRITY`） | 可能串文件或存储损坏，与试点立即暂停条件相关 |
| 安全 | 越权拒绝次数异常；签名校验失败、nonce 重放、令牌过期异常 | 可能是攻击或缺陷 |
| 合规 | 出口合规拦截数量异常；合规检查不可用 | 回复无法安全发出 |
| 依赖 | Dify／模型调用失败、超时、限流（M2b 后） | 问答与抽取不可用 |
| 依赖 | IM 回调失败、推送发送失败（接入后） | 经纪收不到通知 |
| 数据 | 数据库写入失败、审计写入失败、磁盘空间不足 | 审计写入失败会使业务操作回滚 |
| 数据 | 备份失败；恢复演练逾期 | 故障时无法恢复 |
| 基础 | 证书即将到期；服务器时钟偏差 | 证书失效；签名请求被拒 |
| 发布 | 生产配置启用 mock 被拦截或启动失败 | 防止模拟文件进入生产 |

错误代码含义见 [Python 对接契约](../../python-integration-contract.md) §5。

## 6. 回退方案

### 6.1 分级

| 级别 | 触发 | 动作 | 决策人 |
| --- | --- | --- | --- |
| 单产品暂停 | 门户变化、某产品核验失败 | 运营暂停该产品：新任务被拒，排队任务转人工，在途任务继续核对（[产品暂停与人工处理](../../product-operations.md)） | 待确认 |
| 能力降级 | Dify／模型不可用；IM 或推送故障 | 明确提示问答／抽取不可用，经纪改用表单；通知失败时在 APP 任务列表查看 | 待确认 |
| 版本回退 | 新版本缺陷 | 回到上一发布版本 | 待确认 |
| 全面暂停 | 触发[试点立即暂停条件](pilot-plan.md)或重大安全事件 | 停止接收新任务，保全日志与审计，逐个核实在途任务 | 待确认 |
| 数据恢复 | 数据损坏或丢失 | 按第 2 节从备份恢复，恢复后真实在途任务转人工 | 待确认 |

### 6.2 回退原则

- 任何情况下**不静默切换到 mock**，不把模拟文件当官方文件交付（[AGENTS.md](../../../AGENTS.md) §2 第 2 条）。
- 不自动重跑真实任务；门户结果不确定的任务转人工核实。
- 关闭某个产品或 adapter 不影响已生成文件的下载及其他产品（[交付计划](../../delivery-plan-v1.md) §5.2）。
- 数据库结构变更须可回退或向前兼容；做法待确认。

### 6.3 回退包（上线前备好）

上一可用版本及配置快照、数据库迁移与回退说明、回退步骤与执行人、回退后验证清单（登录、提交、下载、隔离、人工队列）、对经纪的通知方式与文案（待确认）。
