## 2. 每项还需一并确认

1. **每日任务上限**：“一天”按哪个时区、从几点起算；取消、失败、被拒、转人工的任务是否计入（同一幂等键的重复提交不算新任务）；是否另设机构总上限；达到上限时直接拒绝并提示，还是可申请临时放宽，由谁批准。
2. **单账号并发**：共有几个执行账号，按经纪还是按机构分配（只登记 `credentialRef` 和负责人，不写密码）；保司是否限制次数或频率。不同 `credentialRef` 若实际指向同一账号，系统无法自行识别，须由集成确认一一对应（[Python 对接契约](../../python-integration-contract.md) §4）。
3. **最大排队时长**：超时后转人工、取消并通知经纪，还是只告警；工作时间与非工作时间是否区分。目标值应参考试点前实测的人工基线（交付计划 §7“交付时延”）。
4. **人工接管负责人**：主负责人和备份人；工作时间与非工作时间安排；响应时限；升级对象。此人需要运营角色权限，并能登录保司门户核实结果——关闭真实任务前必须在门户核实（[产品暂停与人工处理](../../product-operations.md)）。
5. **文件存储期限**：按文件类型分别确定（官方 PDF／讲解包导出件／RPA 截图与执行证据）；到期删除还是归档；备份中的副本何时删除；客户撤回授权或要求删除时如何处理；经纪离职后文件归谁。
