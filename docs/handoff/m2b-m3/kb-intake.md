# 知识库资料接收规范（M3）

日期：2026-09-23　状态：规范草案，知识库尚未建立，未接收任何资料
收件人：业务负责人、产品专家、合规负责人、运营
关联：集合划分见 [Dify 工作流实施计划 · 知识库组织](../../dify-workflow-plan.md#知识库组织)；
资料使用授权与留存问题见 [privacy-questions.md](privacy-questions.md)（D3、C4）

## 1. 原则

- 只接收**审核通过**的资料。员工知识库内容不直接复用，逐份走本规范。
- 每份资料必须有来源、版本、生效日期和失效日期（或复核截止日）。缺任何一项不入库。
- 已失效资料禁用，不与现行版本同时被检索。
- 可见范围由业务后端按登录身份决定，不由模型判断。
- 知识库不收客户个人资料、真实保单、计划书 PDF，也不收任何账号、密码、Cookie 或含凭据的截图。
- **红线**：知识库中的金额、收益、现金价值、保费、保障金额等数字，问答时不复述、不推算（见
  [AGENTS.md §2 红线 1](../../../AGENTS.md)）。需要这类数字的问题，引导经纪查看官方计划书。

## 2. 资料类别

| 类别 | 典型内容 | 来源要求 | 所属集合 | 默认可见 | 进入经纪问答 |
| --- | --- | --- | --- | --- | --- |
| 产品条款 | 保单条款、官方产品说明书 | 保司官方发布或正式提供；必须对应产品版本 | 1. 产品条款与官方说明 | 经纪、运营 | 是 |
| 产品资料 | 产品小册子、官方 FAQ、产品要点 | 同上 | 1（按 `document_type` 区分；是否独立成集合待确认） | 待确认 | 是（经合规确认后） |
| 操作流程 | 投保流程、材料清单、内部服务规范 | 机构内部正式发布 | 2. 内部操作流程和服务规范 | 经纪、运营 | 是 |
| 合规红线 | 禁用表述、批准话术、披露要求 | 合规负责人提供 | 3. 合规红线与批准话术 | 主要供合规审查使用；对经纪是否可见待确认 | 待确认 |
| 门户手册 | 保司门户操作步骤 | 保司或运营整理 | 4. 保司门户操作手册 | 仅运营 | **否** |

补充规则：

- 产品资料里的利益演示表、示例保费等数字页：入库前在元数据标出页码，问答不输出其中数字。
- 投保年龄、冷静期天数这类非金额数字，能否带出处输出，由合规负责人决定（待确认）。在决定前按不输出处理。
- 合规红线变更后，出口审查的规则版本和回归用例需同步更新，不能只改知识库。

不接收：客户个人资料、未确认来源的转发文件、竞品未经证实的说法、已停售产品未标注状态的资料、
含账号密码或会话信息的截图。

## 3. 元数据模板

每份资料一条记录。字段名与 Dify 计划中的元数据保持一致（`insurer`、`product_id`、`document_type`、
`version`、`effective_date`、`jurisdiction`、`audience`、`status`），并补充本规范要求的字段。

```yaml
doc_id: KB-待分配             # 由知识库管理员分配，全局唯一
title:                        # 资料原标题
collection:                   # product_terms | operations | compliance | portal_manual
document_type:                # 条款 | 产品说明书 | 产品小册子 | FAQ | 操作流程 | 服务规范 | 合规红线 | 批准话术 | 门户手册
insurer:                      # 保司；内部资料填“内部”
product_id:                   # 须与产品目录一致；非产品资料填 "-"
product_version:              # 官方产品版本；非产品资料填 "-"
version:                      # 本资料的版本号
jurisdiction:                 # 适用法域，待填
language:                     # 简体 | 繁体 | 英文

# 来源
source_type:                  # 保司官方 | 保司提供 | 内部发布 | 合规部门
source_ref:                   # 受控存储引用或官方链接；不填个人电脑路径
obtained_at:                  # 取得日期
submitted_by:                 # 提交人
disclosure_permitted:         # 是否获准向渠道经纪披露：是 | 否 | 待确认
file_sha256:                  # 原文件 hash
pages:                        # 总页数
figure_pages: []              # 含金额／收益／利益演示数字的页码

# 生效与失效
effective_date:               # 生效日期
expiry_date:                  # 失效日期；无明确失效日期时填复核截止日
review_due:                   # 下次复核日期
supersedes:                   # 被本资料替换的 doc_id；没有则留空

# 可见权限
audience:                     # broker | operator | compliance，可多选
tenants:                      # all 或指定机构编号列表
chat_enabled:                 # 是否进入经纪问答：true | false（门户手册固定 false）

# 审核
reviewers:
  source_check:   { name: , date: , result: }   # 产品专家：来源与版本
  content_check:  { name: , date: , result: }   # 产品专家／业务：适用范围、数字页、个人资料
  compliance_check: { name: , date: , result: } # 合规负责人：披露许可、红线
approved_at:
change_note:                  # 本版本变更说明
status:                       # draft | in_review | active | superseded | expired | withdrawn
```

所用 Dify 版本能否按这些元数据过滤检索，见 [request-dify.md](request-dify.md) 第 2 节，待确认。
不能过滤的字段，由业务后端在检索范围上控制。

## 4. 提交要求

- 通过受控存储提交（位置待确认），不通过聊天或个人邮箱发送附件。
- 优先提交可复制文字的官方 PDF 原件；扫描件需经人工核对识别结果后才能入库。
- 一份文件对应一个版本，不合并多个版本；文件内不得有手写批注或个人信息。
- 同时提交填好的元数据记录。

## 5. 审核流程

| 步骤 | 负责角色 | 动作 | 通过后状态 |
| --- | --- | --- | --- |
| 1. 登记 | 提交人 | 上传文件，填写元数据 | draft |
| 2. 来源核验 | 产品专家 | 核对是否官方来源，产品与版本是否一致，日期是否正确 | in_review |
| 3. 内容审核 | 产品专家／业务 | 核对适用范围、可见范围，标出数字页，确认无个人资料 | in_review |
| 4. 合规审核 | 合规负责人 | 确认可向渠道披露，内容不违反红线 | in_review |
| 5. 入库检查 | 后端／AI | 导入测试集合，检查分段是否保留页码；抽样提问核对命中片段与出处 | in_review |
| 6. 发布 | 知识库管理员 | 启用，记录版本和变更说明；被替换的旧版同时禁用 | active |

- 提交人不能担任本份资料的审核人。
- 任一步不通过，退回 draft 并写明原因。
- 每步审核人姓名待业务负责人指定（待确认）。

## 6. 过期与变更处理

| 情况 | 处理 |
| --- | --- |
| 临近失效 | 提前提醒资料负责人（提前天数待确认，建议 30 天） |
| 到达失效日期 | 当天自动禁用，状态改为 expired，不再被检索 |
| 发布新版本 | 新版 active 的同时，旧版改为 superseded 并禁用；新旧不同时被检索 |
| 无明确失效日期 | 按 `review_due` 定期复核（周期待确认）；逾期未复核按 expired 处理 |
| 产品停售或下架 | 相关资料标注并禁用；问答对该产品回答“无法核实”或提示资料已失效 |
| 发现错误 | 立即改为 withdrawn 并禁用（时限待确认）；修正后重新走审核流程 |
| 禁用后 | 重跑 [acceptance-cases.md](acceptance-cases.md) 中受影响的 M3 用例 |

没有有效资料时，问答一律回答“无法核实”，不用过期资料补答。
失效资料是物理删除还是禁用保留，按 [privacy-questions.md](privacy-questions.md) C4 的结论执行。
