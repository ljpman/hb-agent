# M1b · 真实链路验收用例

起草：2026-09-23 · 范围：首家保司、首个产品（待香港确认，见 [request-hk.md](request-hk.md) R05）· 状态：用例草案，**均未执行**

"红线"一栏对应 [AGENTS.md](../../../AGENTS.md) §2 的编号：

| 编号 | 红线 |
| --- | --- |
| ① | 模型不生成任何金额／收益数字，无法可靠核对时转人工 |
| ② | real ≠ mock 严格分离，不静默回退 mock |
| ③ | 凭据只用 `credentialRef` |
| ④ | 认证、租户隔离、幂等、确认快照、任务恢复语义不被破坏 |
| ⑤ | PDF 交付前核验 |
| ⑥ | 出口审查在发送前完成 |
| ⑦ | 诚实，不假装已接通或已支持 |

错误码见 [对接契约草案](../../python-integration-contract.md) §5。本地适配器已有的离线防护见契约 §4"当前骨架的接收规则"；这些防护都要在真实链路上重新验证，离线测试通过不算 M1b 验收。

## 1. 通用前置条件

- **G1** 真实 adapter 由服务端配置启用；`/api/bootstrap` 显示 Python 已配置；任务 `isMock: false`。生产配置下无法使用 mock。
- **G2** 使用按 [sample-spec.md](sample-spec.md) 提交并已签认的样本。除负样本外只用 S01–S05 的参数。
- **G3** 测试账号已获门户使用授权；凭据放在受控存储里，任务只携带 `credentialRef`。
- **G4** 确定性 PDF 核验器已按样本 `checklist.md` 的规则实现（M1b 交付物）。
- **G5** 在获准环境执行。每条用例记录 jobId、attemptId、状态变化、错误码、审计条目和必要的脱敏截图，保存在受控位置。
- **G6** 需要香港配合触发的场景（MFA、会话过期、门户拒绝等），触发方式待香港确认（R08、R12）。

**当前本地实现与 M1b 的差距**（2026-09-23 更新）：

- 已离线实现：真实任务只有经业务服务的确定性核验器通过才能从 `validating` 进入 `succeeded`；结构不合格或值不一致本地判 `PDF_MISMATCH`；核验通过后释放账号占用。规则见 [对接契约](../../python-integration-contract.md) §4"候选文件取回与本地核验"。
- 仍待 M1b：首个产品的核验规则（按签认的 `checklist.md` 编写；目前没有任何真实产品规则，真实候选文件一律转人工）；香港侧文件取回方式（`fetchArtifact` 尚无默认实现）；真实任务的讲解包（目前返回 `PACKAGE_NOT_READY`）。
- 样本到位后先运行 `node scripts/check-samples.mjs <样本包目录>` 做接收检查。

## 2. 每条用例都要检查的通用结果

- **C1** 没有任何未通过核验的文件进入 `succeeded` 或可下载状态（⑤）。
- **C2** 日志、审计正文、错误提示和聊天里没有密码、验证码、Cookie、会话 token、门户内部链接或堆栈。账号占用记录只存引用的 hash，不存凭据或原始引用（③）。
- **C3** `isMock` 与实际执行的 adapter 一致；真实链路失败时不回退 mock（②）。
- **C4** 经纪看到的是脱敏、可操作的状态提示；没通过核验就不说"已成功"或"官方文件已生成"（⑥⑦）。
- **C5** 其他经纪或其他租户即使拿到 jobId，也不能查看或下载（④）。

## M1B-01 正常出件

- **前置条件**：G1–G6；S01–S05 已签认；测试账号空闲。
- **步骤**：
  1. 经纪按 S0x 的参数创建草稿并确认，提交时带 `Idempotency-Key`。
  2. Worker 调用香港服务；香港原样回传 jobId、attemptId，返回 `status: validating`、`artifactRef`、`source`，`isMock: false`。
  3. 核验器对取回的文件执行该样本 `checklist.md` 的全部规则。
  4. 本人下载；另一经纪用同一 jobId 尝试下载。
  5. 用同一幂等键再提交一次。
  6. S01–S05 每组各执行一遍。
- **期望结果**：
  - 状态依次为 `queued → running → validating → succeeded`，`isMock: false`。
  - 文件类型、来源、产品版本和每个参数都与确认快照逐项一致；核验记录写明每项的页码和比对规则；保存原文件 sha256，文件未被改写。
  - 系统对外展示的数字只有两类：确认参数的原样复述，以及核验通过的 PDF 字段；没有任何模型生成的金额。
  - 本人能下载，其他经纪被拒绝。
  - 重复提交返回原任务，门户上没有第二次生成。
  - 核验通过后释放账号占用（M1b 新增）。
- **红线**：①②④⑤⑦
- **待香港确认**：一次生成在门户上是否还有其他副作用（例如自动保存草稿或提交申请）。

## M1B-02 缺字段

- **前置条件**：G1–G5。
- **步骤**：
  1. 在表单或自然语言抽取中逐个去掉必填字段，尝试确认。
  2. 用测试工具直接向香港服务发送缺字段的契约请求（绕过前端，仅用于验收）。
  3. 若产品有吸烟状态这类布尔字段，提交明确的 `false`。
- **期望结果**：
  - 步骤 1：草稿不能确认，界面指出缺哪一项，不猜值；不调用香港服务。
  - 步骤 2：香港服务在登录门户之前返回 `PARAM_INVALID`，附脱敏的字段名；不自动补默认值，不操作门户。任务 `failed`，不重试，账号占用释放。
  - 步骤 3：`false` 被当作有效值原样传给香港，并在 PDF 核对中出现，不被当成缺失。
- **红线**：①（不推测、不补值）④（确认快照）
- **待香港确认**：脚本是否在登录前校验必填项；有没有脚本自动补默认值的字段。

## M1B-03 保司拒绝参数

- **前置条件**：G1–G6；负样本 N01（能通过本地 schema 校验、但被门户拒绝的组合）。没有 N01 时本用例挂起，不用模拟结果代替。
- **步骤**：按 N01 创建并确认任务，执行。
- **期望结果**：
  - 门户在生成之前拒绝：香港返回 `PARAM_INVALID`，任务 `failed`，提示"参数需修改"；账号占用释放，不自动重试。经纪修改后必须重新确认，产生新版本。
  - 无法确定拒绝发生在生成前还是生成后：返回 `RESULT_UNKNOWN`，任务 `awaiting_manual`，账号占用保留。
  - 门户的拒绝原文只以脱敏摘要展示，不暴露内部链接。
- **红线**：①④⑦
- **待香港确认**：`PARAM_INVALID` 只在"门户没有生成任何计划书"时返回（契约 §4 要求接入前验证）。

## M1B-04 MFA 失败或超时

- **前置条件**：G1–G6；一个能可控触发 MFA 的测试账号。
- **步骤**：分别制造以下情况：
  1. 登录时触发 MFA；
  2. MFA 输入错误；
  3. MFA 在截止时间内没有完成。
- **期望结果**：
  - 情况 1、2 返回 `MFA_REQUIRED`，情况 3 截止后为 `RESULT_UNKNOWN`；任务都进入 `awaiting_manual`。
  - 不绕过 MFA，不反复重试导致锁号。
  - 验证码或 MFA 内容不出现在日志、审计、聊天或错误提示中。
  - 账号占用保留，直到运营在门户核实后关闭任务；截止后才到的结果不会自动交付。
- **红线**：③④⑦
- **待香港确认**：MFA 类型和接收人；人工完成 MFA 后是继续原任务，还是必须新建任务。

## M1B-05 跳回登录页

- **前置条件**：G1–G6；负样本 N02（会话失效时脚本实际拿到的内容），或能可控地让会话过期。
- **步骤**：
  1. 填表途中会话失效；
  2. 下载时会话失效，拿到的是登录页（例如 HTTP 200 的 HTML，或扩展名为 `.pdf` 的登录页内容）。
- **期望结果**：
  - 香港服务识别出来：返回 `AUTH_REQUIRED`，任务 `awaiting_manual`。
  - 香港服务没识别、仍返回候选文件：本地核验器识别出不是 PDF 或是登录页，判 `PDF_MISMATCH`，任务 `awaiting_manual`。
  - 该文件不会成为可下载成果，也不会标成"官方文件"。
- **红线**：②⑤
- **待香港确认**：脚本凭什么判断到了登录页（地址、页面元素或其他）。

## M1B-06 下载到其他任务的文件

- **前置条件**：G1–G5；两组在 PDF 上有可见差异的样本 A（例如 S01）和 B（例如 S02）。
- **步骤**：
  1. A、B 先后执行，或用不同账号并行执行；检查香港侧的下载目录和文件名。
  2. 注入：让 A 的结果指向 B 的 PDF（通过测试工具，或香港提供的测试开关）。
  3. 注入：返回的 jobId 或 attemptId 与请求不一致。
- **期望结果**：
  - 步骤 1：每个任务的文件放在独立位置，不复用固定文件名。
  - 步骤 2：核验器发现 PDF 参数与 A 的确认快照不一致，判 `PDF_MISMATCH`，A 进入 `awaiting_manual`，不交付 B 的文件；B 不受影响。
  - 步骤 3：判 `RESULT_UNKNOWN`，任务 `awaiting_manual`（本地已有离线防护，需在真实链路复验）。
- **红线**：④⑤
- **说明**：如果 PDF 上没有能区分任务的标识（[sample-spec.md](sample-spec.md) §7.1 F9 写"无"），只能靠参数比对和目录隔离；此时参数完全相同的两个任务无法靠文件内容区分，需要在报告里写明这一残余风险。

## M1B-07 非 PDF

- **前置条件**：G1–G5。
- **步骤**：通过测试工具或香港测试开关，让候选文件依次为：HTML、图片、空文件、截断或损坏的 PDF、加密 PDF、压缩包、扩展名是 `.pdf` 但内容不是 PDF 的文件。
- **期望结果**：
  - 核验器按文件内容判断（不看扩展名），判 `PDF_MISMATCH`，任务 `awaiting_manual`。
  - 文件不保存为可下载成果；经纪看到"文件核验失败，已阻止交付"。
- **红线**：⑤

## M1B-08 产品版本不符

- **前置条件**：G1–G5。
- **步骤**：
  1. 香港返回的 `source.productVersion` 与确认快照不同。
  2. `source` 一致，但 PDF 上印的版本与确认快照不同。
  3. 确认之后、提交之前，本地目录里的产品版本或字段规则变了，用旧确认页提交。
  4. 门户已换新版本，而请求的仍是旧版本。
- **期望结果**：
  - 情况 1：`RESULT_UNKNOWN`，`awaiting_manual`（本地已有离线防护，需复验）。
  - 情况 2：`PDF_MISMATCH`，`awaiting_manual`。
  - 情况 3：不创建任务，返回 `SCHEMA_CHANGED`，要求重新确认。
  - 情况 4：门户尚未生成时香港返回 `PRODUCT_UNAVAILABLE`，发现页面结构变化时返回 `PORTAL_CHANGED`；不用新版本顶替旧版本出件，产品按规则暂停自动执行。
- **红线**：②④⑤
- **待香港确认**：脚本能否读到门户上当前的产品版本；怎样识别门户改版。

## M1B-09 中断重启

- **前置条件**：G1–G5；任务处于 `running`，香港已开始门户操作。
- **步骤**：分别执行以下操作，恢复后用原幂等键再提交一次：
  1. 结束本地业务服务后重启；
  2. 结束香港 Worker 进程后重启；
  3. 断开双方网络，超过截止时间后恢复。
- **期望结果**：
  - 真实 `running` 任务不自动重做；已持久化的执行尝试不再发送；任务进入 `awaiting_manual`（`WORKER_LOST` 或 `RESULT_UNKNOWN`）。
  - 账号占用保留。运营在门户按参考编号核实后，以 `portalChecked: true` 关闭任务并释放账号，审计同时写入。
  - 恢复后才到的结果不会改写状态，也不会自动交付。
  - 幂等重放返回原任务，不新建任务。
  - 香港 Worker 重启后不会自行重跑未完成的门户操作。
- **红线**：④
- **待香港确认**：香港 Worker 重启后的现有行为；门户能否按参考编号查到已生成的计划书（R12）。

## M1B-10 结果不确定转人工

- **前置条件**：G1–G5。
- **步骤**：逐项制造：
  1. 香港响应超过截止时间（当前默认 120 秒，正式值待 R12 耗时数据确定）；
  2. 请求发出后连接中断；
  3. 返回未知错误码、缺少 jobId 或 attemptId、结构不合法；
  4. 返回 `isMock: true`；
  5. 返回 `queued` 或 `running`（异步协议确定之前）；
  6. 返回 HTTP 重定向。
- **期望结果**：
  - 全部进入 `awaiting_manual`：第 4 项为 `ADAPTER_MISMATCH`，其余为 `RESULT_UNKNOWN`。
  - 不自动重新提交；人工队列显示原因；运营先核实门户再处理。
  - 不宣称已生成计划书。
- **红线**：①②④⑦
- **说明**：以上各项本地已有离线防护（契约 §4），本用例在真实网络和真实服务上复验。

## M1B-11 同账号并发

- **前置条件**：G1–G5；两个使用同一 `credentialRef` 的任务（来自不同经纪，另测一次不同租户）；另两个使用不同 `credentialRef` 的任务。
- **步骤**：几乎同时提交两个同账号任务；再几乎同时提交两个不同账号任务。
- **期望结果**：
  - 同账号：同一时间只有一个任务在门户执行，另一个等待；前一个结果不确定时账号继续占用，后一个不进入门户。
  - 不同账号：互不阻塞。
  - 门户上没有同账号多会话互踢；万一香港侧发生被踢，受影响任务转人工，不报成功。
  - 两个任务的文件各自核验通过，没有串文件。
  - 占用记录只存引用的 hash。
- **红线**：③④⑤
- **待香港确认**：一个真实账号只对应一个 `credentialRef`；香港侧是否另有跨部署的账号锁（契约 §4）。

## 4. M1b 完成门槛

- M1B-01 对全部 3–5 组样本通过；M1B-02 至 M1B-11 全部通过。因缺香港条件而挂起的用例要写明原因和负责人；挂起用例未通过前，M1b 不标记完成。
- 任何一次未通过核验的文件被标 `succeeded` 或可下载，即判 M1b 不通过，修复后全部用例重跑。
- 现有离线测试全部通过：`node --test tests/*.test.mjs`。
- 每条用例的证据由测试和产品专家（写角色）签认。
- 通过后只说明"首家保司、首个产品、该官方版本"已验收，不扩大到其他产品或保司。
