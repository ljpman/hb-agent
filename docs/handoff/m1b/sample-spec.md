# M1b · 官方样本提交规范

起草：2026-09-23 · 对应请求单：[request-hk.md](request-hk.md) R11

本规范说明"官方输入 ↔ 官方 PDF"样本怎么准备、怎么脱敏、怎么提交。样本用来编写确定性核验规则，也是验收基准。系统**不计算、不推测**任何金额，只核对确认过的输入和官方 PDF 是否一致。

下文示例里的字段代码和值都是 `<占位>`。真实字段以 R06 的字段映射为准，不知道的写"待香港确认"。

## 1. 数量与范围

- 3–5 组，**同一保司、同一产品、同一官方版本**（R05 选定）。有 1 组就可以开始开发，验收需要 3–5 组。
- 建议覆盖以下情况，只用产品专家确认有效的组合，不为凑数虚构：

  | 编号 | 用途 |
  | --- | --- |
  | S01 | 普通参数 |
  | S02 | 另一缴费方式或币种 |
  | S03 | 年龄或金额的合法边界值 |
  | S04–S05 | 其他常用组合（可选） |

- 可选负样本：
  - **N01**：被门户拒绝的输入，附拒绝提示（截图或文字）。
  - **N02**：会话失效时脚本实际拿到的内容（例如登录页或错误页的原始文件）。
  - 这两类用于 [acceptance-cases.md](acceptance-cases.md) 的"保司拒绝参数""跳回登录页"用例。
- 所有 PDF 必须由保司门户官方生成。手工排版、改过数字或来源不明的文件不能作为样本。

## 2. 目录结构

```text
m1b-samples-<批次号>/
├── README.md              提交说明：批次号、提交人角色、提交日期、样本数量、已知问题
├── manifest.json          样本索引（§5.2）
├── product/
│   ├── field-map.md       字段映射，按启动包 §5 模板
│   └── version-evidence/  产品版本出处的脱敏截图
├── samples/
│   ├── S01/
│   │   ├── input.json     输入参数（§3）
│   │   ├── meta.json      元数据（§5.1）
│   │   ├── <PDF 文件>     官方 PDF，命名见 §4
│   │   ├── checklist.md   输入 ↔ PDF 核对表（§7）
│   │   └── portal/        可选：门户关键页面脱敏截图
│   └── S02/ …
└── negative/              可选负样本
    ├── N01/  input.json、meta.json、拒绝提示截图或文本
    └── N02/  meta.json、会话失效时拿到的原始文件
```

- 目录名和文件名只用 ASCII 字母、数字和 `-` `_` `.`，不含姓名、证件号或账号名。
- 整包附 sha256，经双方约定的受控渠道传递（渠道待确认）。

字段映射表模板见 [第一步启动包](../../phase-01-start-pack.md) §5，样本索引可同时登记到该文件 §4，这里不重复。

## 3. 输入参数 `input.json`

```json
{
  "specVersion": "1",
  "sampleId": "S01",
  "productCode": "<待香港确认>",
  "productVersion": "<待香港确认>",
  "fieldMapVersion": "<field-map.md 的版本>",
  "params": {
    "<字段代码A>": "<值>",
    "<布尔字段代码>": false,
    "<金额字段代码>": "<十进制字符串>",
    "<币种字段代码>": "<ISO 4217 代码>"
  },
  "portalEntries": [
    {
      "fieldCode": "<字段代码A>",
      "portalLabel": "<门户上的标签原文>",
      "control": "<输入框 | 下拉 | 单选 | 勾选 | 日期>",
      "enteredValue": "<门户上实际输入或选择的内容>",
      "source": "entered"
    },
    {
      "fieldCode": "<字段代码C>",
      "portalLabel": "<门户上的标签原文>",
      "control": "<…>",
      "enteredValue": "<门户或脚本带出的默认值>",
      "source": "portal-default"
    }
  ]
}
```

规则：

- `params` 和 `portalEntries` 要覆盖这次生成时门户上**所有有值的字段**，包括门户或脚本自动带出的默认值（`source` 写 `portal-default` 或 `script-default`）。
- 金额用十进制定点字符串，不用浮点数、科学记数法或千分位；币种单独一个字段。
- 布尔值写 `true` 或 `false`。明确的否定（例如非吸烟）必须写 `false`，不能省略；确实未知写 `null`，并在 `meta.json` 的 `knownIssues` 里说明。
- 日期写 `YYYY-MM-DD`。下拉等枚举字段，`params` 写选项代码，`enteredValue` 写门户上显示的选项文字。
- 不加门户上没有的字段，不写推测值。

## 4. PDF 命名与要求

- 命名：`<sampleId>__<产品代码>__<产品版本>.pdf`。版本里有空格、斜杠等字符时替换成 `-`；产品代码未知写 `unknown`，并在 `meta.json` 说明。
- 门户原始下载文件名的规则写进 `meta.json` 的 `download.originalFilenamePattern`，用占位描述，不含个人信息。
- 提交门户下载的原文件。需要事后脱敏的，按 §6 处理后另存，并在 `meta.json` 注明。
- 不加密，不另加水印，不压缩重存，不"打印成 PDF"。

## 5. 元数据

### 5.1 每组样本的 `meta.json`（必填）

必须包含：产品全称、代码、版本及其出处；生成时间（含时区）；生成方式（脚本或人工）及脚本版本；门户环境；门户路径；门户参考编号格式；下载方式及链接有效期；PDF 的 sha256、大小、页数、能否提取文字、是否加密；脱敏方式及核对人；组合有效性的确认人；留存许可；已知问题。

```json
{
  "sampleId": "S01",
  "insurerRef": "<保司内部代号，待香港确认>",
  "product": {
    "officialName": "<门户显示的产品全称>",
    "productCode": "<…>",
    "productVersion": "<…>",
    "versionEvidence": "<版本在 PDF 第几页什么位置、门户哪一页显示>"
  },
  "generation": {
    "generatedAt": "<YYYY-MM-DDThh:mm±hh:mm，门户实际生成时间>",
    "method": "<script | manual>",
    "scriptRef": "<脚本 commit 或版本；人工生成写 null>",
    "operatorRole": "<角色，例如运营或经纪；不写姓名>",
    "portalEnvironment": "<生产 | 测试 | 培训，待香港确认>",
    "portalPath": ["<一级菜单>", "<二级菜单>", "<产品页>", "<生成或下载按钮文字>"],
    "portalReferenceFormat": "<门户报价或计划书编号的格式；具体值如能关联真实客户则替换为占位>"
  },
  "download": {
    "method": "<direct | temporary-link | email | other>",
    "linkValidity": "<临时链接有效期；没有写 null>",
    "originalFilenamePattern": "<原始文件名规则，用占位描述>"
  },
  "pdf": {
    "fileName": "<按 §4 命名>",
    "sha256": "<提交文件的 sha256>",
    "sizeBytes": "<整数>",
    "pageCount": "<整数>",
    "textExtractable": "<true | false>",
    "passwordProtected": "<true | false>"
  },
  "desensitization": {
    "approach": "<fictitious-at-generation | redacted-after-generation | none-needed>",
    "modifiedPdf": "<true | false>",
    "changes": ["<改了哪一页哪个位置>"],
    "checkedByRole": "<核对人角色>",
    "textLayerChecked": "<true | false>"
  },
  "validity": {
    "confirmedByRole": "<产品专家等角色>",
    "confirmedAt": "<YYYY-MM-DD>",
    "note": "<为什么这组参数有效>"
  },
  "retention": "<该样本允许的用途和保留期限，待确认>",
  "knownIssues": []
}
```

- `portalPath` 写菜单和页面名称，不写带令牌或会话参数的 URL。
- 负样本也要有 `meta.json`，不适用的字段写 `null`。

## 6. 脱敏规则

**首选：生成时就用虚构资料。** 如果门户允许试算或演示方式，用虚构的被保险人资料生成，PDF 就不需要事后改动。

只能使用历史真实 PDF 时：

- **定价相关的输入不能改**（年龄或出生日期、性别、吸烟状态等，以 R06 为准），改了就无法核对。如果这些字段本身就是真实客户资料，这份 PDF 不适合作样本，请改用虚构资料重新生成。
- **必须移除或替换**：姓名、证件号、电话、邮箱、地址、真实保单号或申请号、经纪或代理人姓名与编号、门户账号名、带签名或令牌的 URL、包含个人信息的二维码或条码。统一替换成固定占位（例如 `REDACTED`），不要用看起来像真人的假名。
- **不得改动**：所有金额和利益表、保费、保障额、产品名称和版本、页码、页眉页脚里的版本信息、免责声明，以及不含个人信息的生成日期。
- **做法**：用能真正删除文字层的工具。只盖黑框不算脱敏，黑框下的文字仍可复制。处理后全选复制一遍或用文字提取工具检查，并清理 PDF 属性里的作者等个人信息。
- 在 `meta.json` 的 `desensitization` 里记录改了哪里、由谁（角色）核对。
- 截图同样处理：裁掉账号名、地址栏里的令牌和其他客户信息。
- 负样本同样适用以上规则。

## 7. 输入 ↔ PDF 逐项核对清单（`checklist.md`）

每组样本一份，由产品专家填写并签认（写角色）。我方会把每一行转成确定性核验规则，所以每行都要写清"在 PDF 哪里、怎样稳定地找到"。

### 7.1 文件与来源

| # | 核对项 | 期望 | PDF 实际值及页码／位置 | 一致 |
| --- | --- | --- | --- | --- |
| F1 | 文件类型 | 能正常打开的 PDF，不是 HTML、图片或空文件 | | |
| F2 | 不是登录页或错误页 | 首页是计划书内容 | | |
| F3 | 文字可提取 | 是；扫描件请注明 | | |
| F4 | 保司标识 | 与 `meta.json` 一致 | | |
| F5 | 产品全称、产品代码 | 与 `meta.json` 一致 | | |
| F6 | 产品版本或生效日期 | 与 `meta.json` 一致 | | |
| F7 | 生成日期 | 与 `generatedAt` 同一天 | | |
| F8 | 门户参考编号（如有） | 格式与 `meta.json` 说明一致 | | |
| F9 | 能区分不同任务的标识 | 列出 PDF 上哪些内容能把这份文件和其他任务的文件区分开（参考编号、生成时间、虚构被保险人等）；没有请写"无" | | |

### 7.2 参数逐项（`input.json` 每个字段一行）

| # | 字段代码 | `input.json` 值 | PDF 显示原文 | 页码／定位方式 | 比对规则 | 一致 |
| --- | --- | --- | --- | --- | --- | --- |
| P1 | `<字段代码A>` | | | 例：第 N 页"<标签>"右侧 | 原文相同，或格式归一后相同（写明归一规则：千分位、币种符号、日期格式等） | |
| P2 | … | | | | | |

- `input.json` 里每个字段都要有一行，门户默认值（`portal-default` / `script-default`）也要核对。
- PDF 上没显示的字段写"PDF 未显示"，并说明还能用什么确认门户采用了这个值（例如门户截图）。
- 输入和 PDF 口径不同时（例如输入出生日期、PDF 显示年龄），写明换算规则和确认人。我方不自行推断规则。

门户计算出来的数值（如利益表、保障额等，以实际 PDF 为准）不是输入，不能拿输入核对。这里只登记页码和表格标题，供后续讲解包的事实表使用。本清单**不判断这些数值对不对，也不做任何推算**。

## 8. 需要退回重做的情况

- 缺 `input.json`、`meta.json` 或 `checklist.md`。
- 各样本的产品版本不一致（负样本除外）。
- 文字层还能复制出姓名、证件号等个人信息。
- 定价相关输入被改动过。
- PDF 打不开、加了密，或不是门户官方生成。
