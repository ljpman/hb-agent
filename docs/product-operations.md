# 产品暂停与人工处理（本地实现）

对应开发清单 C04。当前仅验证演示产品与离线适配器；真实门户异常识别、账号范围和现场处理仍需 M1b 联调。

## 运营操作

1. 工作台切换为演示运营身份，进入「产品与资料」。
2. 填写暂停原因，选择「暂停新任务」。该状态仅影响当前租户的该产品。
3. 新草稿和新任务提交被拒绝；旧确认页也不能绕过暂停。已有任务的幂等重放仍返回原任务。
4. 排队任务在 worker 下次检查时转人工；领取与提交结果之间发生暂停也会被拦截。已经进入 running / validating 的任务继续处理结果，不通过暂停来假定门户执行已取消。
5. 核实异常后填写恢复原因，选择「恢复新任务」。人工队列保持原状态，不自动重跑。
6. 人工队列中只有模拟任务可以手动重新排队，且产品必须已恢复；PDF 错配任务不能直接重试。真实任务需核实门户结果，不提供自动重提入口。
7. 真实任务若持有执行账号占用，关闭前必须勾选「已在门户核实操作结束及结果」。后端要求 `portalChecked: true` 且本地执行租约已结束，才在同一事务里关闭并释放账号。无法核实就保留人工任务和占用，不能靠租约过期自动释放。

适配器报告 `PORTAL_CHANGED` 时自动暂停当前租户的已登记产品；若已经暂停，保留原有原因。当前目录只有演示产品，不能据此声称已具备任一真实保司的产品控制。

## API 与持久化

- `GET /api/products/{id}/availability`：当前租户的暂停状态、原因、修订号和时间。
- `PATCH /api/products/{id}/availability`：仅运营，正文为 `paused: boolean`、`revision: number`、`reason: string`（2–300 字）。身份与租户来自会话；客户端租户字段不参与授权。
- `GET /api/bootstrap` 的 `productAvailability` 用于工作台展示。
- 旧修订号返回 `409 VERSION_CONFLICT`，暂停期间创建返回 `409 PRODUCT_PAUSED`。
- SQLite 保存 `product-control`，状态与审计在同一事务中提交。运营处理人工任务时，任务状态和处理说明也一起提交或回滚。

## 验收证据

`tests/product-control.test.mjs` 覆盖角色／租户隔离、确认页绕过拒绝、幂等重放、排队竞态、重启、自动暂停、恢复后不自动重跑、审计失败回滚和页面转义。2026-09-23 在隔离的本地演示数据库中完成浏览器操作：切换运营 → 产品与资料 → 暂停并看到原因 → 恢复并看到新状态。

该验证不替代真实门户账号、官方 PDF 或生产发布验收。
