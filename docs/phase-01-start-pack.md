## 2. D1 启动会安排（60–90 分钟）

1. 10 分钟：确认首期结果及已有代码交接方式——官方 PDF、讲解包、客户跟进卡。
2. 20 分钟：经纪说明现有业务一单的输入、操作、等待和输出；香港侧可配合时再演示脚本运行。
3. 15 分钟：说明哪些字段最容易填错、哪些场景不能做、哪些地方需要人工。
4. 15 分钟：从已有脚本中选定最成熟的贯通样板及样本组合，约定资料负责人。
5. 10–20 分钟：登记 APP、账号、部署及人员依赖，确定 D2–D5 负责人。
6. 余下时间：确定验收人和下一次原型走查时间。

不在文档或聊天里填写门户密码、验证码、Cookie 或密钥。这里只登记是否具备访问条件及凭据配置负责人。

## 7. D3 原型与样稿走查

原型要覆盖以下路径，开发交付后由经纪实际点击检查：

- 正常：选客户 → 填参数 → 确认 → 生成中 → 官方 PDF → 讲解包复核 → 跟进卡。
- 缺字段：抽取需求 → 高亮缺失项 → 补充 → 再确认。
- 失败：生成中 → 需要人工 → 查看原因及进展 → 人工处理完成。
- 变更：修改已出方案的参数 → 新确认 → 新版本 → 旧讲解包标旧版本。

讲解包样稿预留六部分：方案概况、缴费安排、主要保障、关键限制、常见问题、来源。先由产品专家写出一份正确样稿，再用作模型输出验收参考。

跟进卡先明确哪些字段可自动写入、哪些需要经纪确认、哪些仅是内部工作状态。
